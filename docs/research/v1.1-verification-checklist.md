# V1.1 核验任务清单（风险排序 · 可执行）

> Stage A.1 / A6 交付物。目的：把"研究条目"升级为"已证实规格"。
> 每项给出：验证对象 → 执行方法 → 判定标准 → 失败影响 → 关联 GAP/Feature。
> **证据纪律**：正文抽验目前只完成 3/36（SRC24、SRC26、SRC28）。其余 33 个公开来源
> 一律视为"目录级证据"，其支撑的具体行为默认 `NEEDS_VERIFICATION`，
> 不得在设计/代码中当事实引用。

## 方法与分级

- **正文抽验**（doc-read）：读原文正文，摘出原句作引证。
- **UI 实测**（ui-observe）：试用账号/演示环境观察字段、按钮、状态。
- **接口观测**（api-observe）：抓官方前端请求（注意合规边界，只用于理解语义）。
- 风险等级：🔴 阻塞型（错了会推翻架构/流程）· 🟡 重要型（改字段/权限）· 🟢 细节型。

## 执行与产出要求

1. 每项产出一段"证据摘录 + 结论 + 引用位置"，写入 `docs/research/v1.1-evidence/`（每任务一文件）。
2. 证实的行为 → 从 `NEEDS_VERIFICATION` 摘除；证伪 → 改规格并留 audit 记录；仍无证据 → 保持标记，**不默认肯定**。
3. 顺序即风险序：V-01/02/03/14 先行（它们共同决定 Rx 状态机与授权这两个地基）。
4. 合规红线：只用公开文档与自有试用账号；不抓取他人数据；UI 截图不得含真实患者信息。
