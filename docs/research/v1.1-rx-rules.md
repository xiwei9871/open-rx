### B. Interaction flow (CONFIRMED SRC01)

```
Create Rx (dashboard | patient page)
  → form screen (F1..F10) → [Create Prescription]
  → Prescription Workspace
       parts/appliances/templates tree+search → canvas placement
       part options (red gear), comments, annotations, tags,
       model source, uploads, resets tab, aligner/IDB tabs
  → [Save]            → status=saved   (any time; fully re-editable)
  → [Sign & Submit]   → Checkout Page → [Submit Prescription]
       → status=submitted, prescription_id issued, workflow bar visible
```

Draft rules: save requires only F1/F2 (+conditionally F9/F10) — patient + lab are the structural
minimum; lab may be `UNIVERSAL_LIBRARY` for drafts (PROVISIONAL confirmation — SRC01 says
library choice "allows you to create, but not submit").

Submit rules: requires a connected lab (not the library sentinel); staff requirements enforced if
configured; `date_needed` validated against ship-date automation; signature required by license
terms (server records signer + timestamp PROVISIONAL).

Edit rules: `saved` and `submitted-pre-checkin` (via unsubmit→saved) editable by practice; lab
can edit `submitted`/`checked_in` content (files, annotations, drawings) — CONFIRMED SRC03/SRC23.
Deletion allowed while saved (restore ≤60 days via support — PARTIAL for our own retention:
EasyRS soft-delete + 60-day restore window mirrors this).

### C. Error handling (evidence + PROVISIONAL)

- Validation errors: missing required fields block create; missing staff fields block when
  configured; date_needed too early blocked by turnaround rule (CONFIRMED mechanisms).
- Duplicate patient: suggestion/autofill flow, not hard-block (CONFIRMED).
- Empty lab option sets (aligner): free-text Additional Notes fallback (CONFIRMED SRC25).
- PROVISIONAL (EasyRS): field errors return 422 with per-field codes; submit on
  disconnected/unavailable lab returns 409; concurrent edit uses optimistic version.

### D. V-01 acceptance cases (S1b E2E)

1. Practice user with edit grant creates Rx for existing patient → saved draft 201.
2. Inline new-patient Rx creates patient + rx atomically; same-surname suggestion surfaced.
3. Universal-library draft saves; submit returns 409 `lab_not_connected`; switching to connected
   lab then submits.
4. Org with `require_clinical_staff=on` rejects submit without impression/submitted staff.
5. `date_needed` earlier than lab days_in_lab+transit → 422 `date_too_early`.
6. Draft re-open preserves parts/options/comments; change date needed + change lab work pre-submit.
7. Submit → status `submitted`, prescription ID assigned, lab-side list shows it, practice can
   unsubmit → status `saved`; second submit keeps same ID (no double billing counter).
8. Post-submit manual attachment succeeds; iTero-source attach post-submit rejected (mirrors
   confirmed stricter rule — PROVISIONAL enforcement).
9. Aligner form: lab option sets populate; empty option set falls back to free text.
10. Cross-org access to the Rx without connection → 403 no metadata leak.

## V-02 Check-in / Unsubmit / Completed — transition table

| Code | From → To | Actor | Precondition | Side effects | Evidence |
|---|---|---|---|---|---|
| T-CREATE | — → `saved` | practice (Edit Rx) | create form min fields | rx row + patient upsert | CONFIRMED SRC01 |
| T-SAVE | `saved` → `saved` | practice | — | version++ | CONFIRMED SRC01 |
| T-SUBMIT | `saved` → `submitted` | practice | connected lab + required fields + signature | Rx ID confirmed; lab notified (dashboard + optional email) | CONFIRMED SRC01/SRC03 |
| T-UNSUBMIT | `submitted` → `saved` | practice | lab has NOT checked in | lab may be notified; same Rx ID (no rebill) | CONFIRMED SRC24 |
| T-ATTACH | `submitted`/`checked_in` → same | either side | manual file only | asset linked to rx + patient | CONFIRMED SRC24/SRC03 |
| T-CHECKIN | `submitted` → `checked_in` | lab | — | **unsubmit now blocked**; practice notified | CONFIRMED SRC03 |
| T-DL-CHECKIN | `submitted` → `checked_in` | lab | download bundle | same effect as check-in — **download is a check-in trigger** | CONFIRMED SRC03 |
| T-LABEDIT | `submitted`/`checked_in` → same | lab | edit buttons exist only here | revision history entry; optional notification | CONFIRMED SRC23/SRC03 |
| T-NOTIFY | any lab-held → same | lab | — | notification object (notify/approve/email-only) | CONFIRMED SRC23 |
| T-COMPLETE | `checked_in` → `completed` | lab (Premium/Enterprise) | check-out | completed_at recorded | CONFIRMED SRC03 |
| T-SHIP | `checked_in`/`completed` → `shipped` (fulfillment) | lab | — | tracking# optional; practice sees shipped | CONFIRMED SRC03 |
| T-RECEIVE | `shipped` → `received` (fulfillment) | practice office | shipped | received_at | PARTIAL SRC02/SRC26 |
| T-DELIVER | `received` → `delivered` (fulfillment) | practice | received | delivered_at | PARTIAL SRC02 |
| T-DELETE | `saved` → deleted(soft) | practice | not submitted/checked-in | restore window 60d | CONFIRMED SRC24/SRC-D6 |
| T-REMAKE | any completed/shipped → new rx linked | practice | remake/repair request | links to original | PARTIAL SRC02/SRC-D2 |

Forbidden (CONFIRMED): unsubmit after check-in; iTero auto-attach after submit; submitting to
unconnected lab; lab editing saved/checked-out Rx (no edit buttons — SRC23).

Irreversible: check-in (locks practice unsubmit), ship, permanent delete of checked-out Rx.
"Completed ≠ production complete": `rx.completed` is the lab workflow step; VisualDLP order
completion is a separate domain — CONFIRMED SRC03/SRC09.

## V-14 Connection revocation & in-flight orders — resolution

Verified facts (CONFIRMED SRC-D4/SRC-D1/SRC-D9):
- Practice-initiated removal exists ("remove your lab from their Connected Labs list").
- **Lab-side disconnect exists since Jan 2024** (SRC-D9) — capability CONFIRMED; its in-flight
  effects are not described.
- In-flight-order behavior on disconnect not documented → `UNKNOWN` for the remaining
  sub-questions (visibility, fulfillment continuation, file access, history).

**EasyRS-owned policy (PROVISIONAL — declared, not inferred):**

1. `connection.status != accepted` blocks `T-SUBMIT` server-side (403 `connection_required`).
2. Existing Rxs keep object-level access for both orgs (Rx carries `practice_org_id` +
   `lab_org_id` grants minted at submit).
3. Checked-in work continues to completion; fulfillment events still flow.
4. Asset access stays bound to granted references — new references can't be created cross-org
   post-disconnect; existing signed/derived links expire naturally.
5. Both orgs retain their own audit history; disconnect event is itself audited.
6. Reconnect does not restore deleted objects; catalog/template visibility is re-granted.

All six items are flagged PROVISIONAL everywhere they appear — EasyRx does not publish them.
