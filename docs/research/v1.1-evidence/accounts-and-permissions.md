# Dossier — Accounts, roles, permissions (V-03)

Sources read in full: SRC01, SRC-D4, SRC-D5, SRC-D1, SRC29.

## EasyRx account model (CONFIRMED SRC01, SRC-D5)

- An EasyRx account has ONE main/administrator login plus unlimited **User Accounts** (individual
  staff logins: clinicians, front desk, in-house lab staff). Only the main/admin login can create
  or edit user accounts (SRC-D5).
- User accounts are validated by email link, can be set Active/Inactive; departed staff should be
  set Inactive.
- "Login information is tracked in a prescription's revision history" — per-user change tracking
  exists on Rxs (SRC-D5).
- **Clinical Staff** is a separate entity: a name list used to record who took impressions and who
  submitted a case. Adding clinical staff does NOT create logins (SRC01).
- ToS (SRC29): one account per entity; sharing a login between non-entity individual users is
  prohibited — consistent with per-user accounts.

## Practice user permission flags (CONFIRMED SRC-D5 — verbatim five flags)

| Flag | Effect when ON | Off-behavior |
|---|---|---|
| Edit Prescriptions | CREATE and EDIT lab prescriptions | View-only on saved/submitted Rx |
| Edit EasyComments | Manage canned comments | — |
| Edit Templates | Edit template names/drawings/info | — |
| Finances | View/download EasyRx invoices generated by Enterprise labs | — |
| In House Lab | ONLY view in-house lab Rx; cannot create/edit Rx, no settings, no templates/comments (checking it unchecks the others; all users can access in-house area by default) | — |

Implications for the V-03 matrix:
- Practice staff CAN create+edit Rx — but only via the `Edit Prescriptions` grant, controlled by
  the practice admin. There is no documented separate "submit" flag; submission rides on edit.
- No documented per-doctor Rx scoping ("doctors see only their own Rx") — UNKNOWN. EasyRS keeps
  its org-wide practice visibility default but may add optional doctor-scoped views PROVISIONAL.
- Practice admin vs staff is a boolean "main login vs user account + flags", not a role matrix.

## Lab-side roles

- Lab account similarly has a main login and user accounts (SRC-D5 covers lab/practice together).
- No per-flag breakdown of lab user permissions was found — the five-flag list is documented in
  the practice account section; lab parity is PARTIAL.
- Lab technician vs admin distinction is not formally documented — UNKNOWN → EasyRS keeps
  lab_admin/lab_technician as PROVISIONAL with technician = non-admin user account semantics.

## Connection permissions (CONFIRMED SRC-D4, SRC-D1)

- Only the practice's main/admin login can send a lab connection request — "user accounts do not
  retain the ability to connect with new labs".
- Lab approves or denies connection requests from its dashboard; email/popup alerts possible.
- Lab can CREATE a practice account (Option 1: lab fills practice info → Create / Create and
  Invite → practice activates, picks plan, enters payment → auto-connected). Lab-created practices
  are auto-connected to that lab.
- Once approved, a practice can submit "permanently … unless they remove your lab from their
  Connected Labs list" — practice-side removal exists; lab-side revocation UX not documented
  (see `connections-and-sharing.md` for V-14).

## Unverified permission items → stay PROVISIONAL/UNKNOWN

- Whether any practice user (vs admin) can Unsubmit — the flag model suggests Edit Prescriptions
  covers it; not stated. PARTIAL → EasyRS default: allow for `practice_doctor`/`practice_staff`
  with rx.write, deny without it.
- Whether labs can delete vs only check-out an Rx — permanent delete exists post-check-out
  (index-level PARTIAL); who may invoke it UNKNOWN.
- Remake/repair request permission — exists as a practice feature; role scope UNKNOWN.
- Tenant support / super-admin PHI access — internal EasyRx roles not public; EasyRS own policy.
