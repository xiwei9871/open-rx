## TASK-0001 租户/机构/地点数据模型与行级隔离

| 关联来源 | SRC01, SRC28 |

### 功能说明
建立 tenant/organization/location 表与 RLS 基线，区分 practice/lab/hybrid 机构类型。

### 业务目标
所有后续业务对象挂接到正确的租户与机构边界，跨机构默认不可见。

### 覆盖 Feature
| Feature ID | 名称 | 证据 | 阶段 | 复杂度 | 研究验收口径 |
|---|---|---|---|---|---|
| IAM-001 | 机构信息及配置 | D1 | MVP | 中 | 新建诊所和实验室且配置互不串用 |
| IAM-002 | 多个诊所地点 | D1 | MVP | 低 | 两处地点能独立关联处方和收货地址 |
| SAFE-002 | 患者数据租户隔离 | T | MVP | 高 | 跨租户ID遍历全部拒绝 |

### 输入输出
输入：机构注册信息（名称、类型、时区）。输出：tenant/org/location 记录与 tenant_id 传播约束。

### 业务规则
- 每个业务行必须携带 tenant_id；查询默认附加租户谓词（ADR-0006 双保险）。
- ORGANIZATION.kind ∈ {practice, lab, hybrid(暂)}；in-house lab 场景预留 hybrid。
- 跨机构读取一律 403 且不泄露对象存在性（E2E-03）。

### 权限要求
平台管理员建租户/机构；org_admin 管本机构与地点。

### 异常处理
- 重复机构名 → 409 + 明确提示
- 非法 kind → 422

### 验收标准
- 可同时存在 practice 与 lab 机构且配置互不串用（IAM-001 验收）。
- 两个 location 可独立关联处方与收货地址（IAM-002 验收）。
- RLS 证明：机构A连接不可读取机构B行（SQL 级测试 + API 级 E2E-03）。

### 测试场景
- RLS 越权矩阵测试
- 双机构同名字段互不冲突
- E2E-03

### 尚未解决的问题

## TASK-0002 登录认证、RBAC、2FA 与账号安全设置

| 字段 | 值 |
|---|---|
| Epic | EPIC-01 |
| 优先级 | MVP |
| 前置依赖 | TASK-0001 |
| 证据等级（覆盖项） | D1/D2/T |
| 关联来源 | SRC02, SRC15, SRC28 |

### 功能说明
用户账号、membership/role、密码策略、时区偏好、TOTP 双因素与登录审计。

### 业务目标
独立员工可登录且权限最小化；高危操作强制 2FA；登录行为全部留审计。

### 覆盖 Feature
| Feature ID | 名称 | 证据 | 阶段 | 复杂度 | 研究验收口径 |
|---|---|---|---|---|---|
| IAM-006 | 独立员工登录账号 | D1 | MVP | 中 | 两个员工账号具备不同权限 |
| IAM-009 | 账号密码管理 | D2 | MVP | 低 | 密码修改后旧会话处理符合设计 |
| IAM-010 | 时区设置 | D2 | MVP | 低 | 同一事件各地点本地时间正确 |
| IAM-011 | 角色/最小权限矩阵 | T | MVP | 中 | 拒绝跨机构读取并记录访问审计 |
| IAM-012 | 双因素认证与访问审计 | T | MVP | 中 | 高风险操作要求二次校验并留痕 |

### 输入输出
输入：邀请、凭证、角色分配、时区。输出：会话令牌、权限谓词、审计事件。

### 业务规则
- 角色矩阵以 permission-matrix.md 为准（PROVISIONAL，默认取严格侧）。
- 高危操作（导出/财务/批量删除）强制已验证 2FA。
- 密码 argon2id 哈希；登录限流与锁定。
- 用户时区影响日期显示与 due_date 计算上下文（IAM-010）。

### 权限要求
org_admin 邀请/停用成员与分配角色；用户管理自己的密码/2FA。

### 异常处理
- 锁定策略触发 → 429 + 恢复指引
- 2FA 未完成的高危操作 → 403

### 验收标准
- 独立员工账号可登录且仅有被授功能（IAM-006）。
- 2FA 开启/关闭/恢复码流程可用（IAM-012）。
- 登录、角色变更产生审计事件（SAFE-001 对接）。

### 测试场景
- RBAC 用例矩阵
- 2FA 注册/恢复
- 限流锁定
- 时区显示一致性

### 尚未解决的问题
- EasyRx 真实角色清单差异（GAP-02）
- staff 可否代 doctor 提交

| 前置依赖 | TASK-0001 |

### 功能说明
roster_member 实体：医生列表、默认医生、临床员工、必填开关；与登录用户解耦。

### 业务目标
处方可归属到名册医生/员工，即使其不是登录用户；停用医生不影响历史处方审计。

### 覆盖 Feature
| Feature ID | 名称 | 证据 | 阶段 | 复杂度 | 研究验收口径 |
|---|---|---|---|---|---|
| IAM-003 | 医生列表及默认医生 | D1 | MVP | 低 | 医生禁用后旧处方仍可审计 |
| IAM-004 | 临床员工名册 | D1 | MVP | 低 | 记录采样与提交人员无需创建账号 |
| IAM-005 | 临床员工必填开关 | D1 | MVP | 低 | 开启时缺字段阻止处方保存 |

### 输入输出
输入：名册条目（类型、姓名、资质、默认标志）。输出：处方归属候选列表。

### 业务规则
- 名册成员 ≠ 登录账号（IAM-004）；linked_user_id 可空。
- 默认医生仅作新建 Rx 预填（IAM-003）。
- 名册必填开关开启时，Rx 提交需选医生/员工（IAM-005）。
- 停用成员保留全部历史归属（IAM-003 验收）。

### 权限要求
org_admin 管理名册；doctor/staff 只读。

### 异常处理
- 停用有未完结处方的医生 → 警告但仍允许，历史留痕

### 验收标准
- 医生被禁用后其历史 Rx 仍可查询审计（IAM-003）。
- 采样/提交人员可记录而无需创建账号（IAM-004）。

### 测试场景
- 禁用后历史可见性
- 必填开关强制
- 默认医生预填

### 尚未解决的问题

### 功能说明
org_connection 授权边：请求、接受、撤销、scope；Rx 提交的前置条件。

### 业务目标
只有 accepted 连接才允许诊所向实验室提交处方（E2E-04）。

### 覆盖 Feature
| Feature ID | 名称 | 证据 | 阶段 | 复杂度 | 研究验收口径 |
|---|---|---|---|---|---|
| IAM-007 | 诊所连接实验室请求 | D1 | MVP | 中 | 申请审批后方可提交正式Rx |

### 输入输出
输入：连接请求（发起方、目标机构、scope）。输出：连接状态机 + 授权边。

### 业务规则
- 连接状态：pending→accepted→(revoked|expired?)；仅 accepted 允许提交。
- 撤销后：已有 Rx 完成生命周期，新提交被拒绝。
- 连接事件写审计并通知对端。

### 权限要求
双方 org_admin 各自批准/撤销自己一侧。

### 异常处理
- 向未连接 lab 提交 → 422 + 提示先建立连接（E2E-04）

### 验收标准
- 未授权 lab 提交立即拒绝并提示连接（E2E-04）
- 撤销即时生效且可审计

### 测试场景
