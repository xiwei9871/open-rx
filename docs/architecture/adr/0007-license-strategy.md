# ADR-0007 开源许可策略：暂不决，给出候选比较与前置审查

- **状态**：OPEN（**未做许可证决定**；不得对外宣称"可安全开源发布"）
- **日期**：2026-10-24

## 背景
目标是可开源、可自托管，但须先完成 clean-room 与依赖审查（GAP-20、主报告 §11）。

## 候选比较（不构成法律意见）

| 许可 | 优点 | 风险/成本 | 适配度 |
|---|---|---|---|
| AGPL-3.0 | SaaS 场景强互惠，防"云白嫖" | 商业用户部署顾虑；贡献者接受度中 | 高（防白嫖诉求存在时） |
| Apache-2.0 | 企业友好、专利授权明确 | 无法防闭源 SaaS 复用 | 中（想最大化采用时） |
| GPL-3.0 | 强 copyleft | SaaS  loophole 仍在；前端依赖牵扯复杂 | 中 |
| BSL 1.1→Apache | 商用保护期后自动开源 | 非 OSI 开源定义（保护期内） | 视商业模式 |
| MIT/BSD | 最宽松 | 无互惠，品牌保护弱 | 低（除非纯库） |

## 前置 Gate（全绿才可宣布开源）
1. 依赖许可证审计（`licensecheck`/scancode 全量，含传递依赖与 Docker 基础镜像）。
2. clean-room 声明：所有实现来自公开需求文档/自研；未复制 EasyRx 代码、素材、文档正文、模型权重（SRC28 §6(c) 亦禁止逆向）。
3. 部件库素材许可（自建或明确授权，GAP-04）。
4. 商标/命名检查（"EasyRx" 为对方商标，项目需独立命名，仓库名 `easyrs` 亦需评估混淆风险 ?）。
5. 贡献者协议（CLA/DCO）选定。
6. 患者隐私承诺：仓库/示例数据零 PHI（SAFE-008）。

## 后果
决定前：仓库保持私有或明确 "license TBD — 暂不授予复用权"；禁止在 README/文档中写死许可证名。
